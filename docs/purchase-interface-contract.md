# Proposed purchase interface

Approved by Codex and Claude A (DevBoard 1791856800_ClaudeA). It adds no working purchase prompts or paid effects. Existing server startup creates the new remote and returns NotReady until the approved implementation is installed. IDs remain absent until actual products/passes exist. Pass keys stay stable as requested by Claude A; the client retains Job.State.jobId for the payout Insurance request.

`Monetization.RequestPurchase(sku, jobId?) -> (ok, reason?)` takes a semantic SKU, never a price, amount or product ID. Pass keys are VIPForeman, DoublePay and HornRadio; product keys are InsuranceClaim, CrewBoost, Cash500, Cash1800 and Cash5500. MonetizationService owns prompt validation and the Roblox prompt call. Returning true means a prompt was requested, not that a purchase succeeded. Only ProcessReceipt grants products; pass ownership is verified through Roblox's server API outside receipt processing.

Server validation requires a loaded profile, an implemented/configured SKU, verified entitlement state, completed first grab, rate limits and no outstanding prompt. During a job the server permits at most one prompt, triggered by the player; only the Insurance offer may appear unsolicited on the payout screen, and clicking it still precedes the platform purchase prompt. Already-owned passes are rejected. Invalid or stale job IDs never select another job's refund. Unsupported effects return NotReady and are not shown as purchasable.

`Monetization.State` publishes `{ready, passes, available}`. Unknown ownership is represented by ready=false; it must not appear as confirmed unowned. Pass flags come only from the server's verified entitlement cache. Availability is true only for real IDs with implemented, tested effects. This state is separate from PublicProfile; no profile fields change in this proposal. Claude A hides purchase buttons before onboarding and for unavailable SKUs, and uses Roblox product information for regional prices rather than hard-coded Robux prices.

PayoutReport gains optional `bonuses[userIdString]`, included in the existing shares and total. Base shares retain the current equal split and join-order remainder rule. Personal bonuses may make final shares unequal; perPlayer remains floor(total / recipientCount), while each player displays their own shares[userIdString]. The UI adds a personal bonus line when nonzero so item values and earned cash remain understandable. Old clients still show the correct final personal share.

Proposed pass math for implementation review: DoublePay doubles the player's job cash; VIP Foreman adds 10% to that player's allocated time-bonus portion (the existing tip), then any cash multiplier applies. Bonuses are integer cash, never extra XP or damage/carry modifiers. All tuning lives in Config. A payout waits for unresolved ownership checks rather than silently omitting an owned benefit. HornRadio grants only cosmetic audio selection; no effect becomes purchasable before its content exists.

Still stubbed and requiring a separate persistent-state review: CrewBoost expiry/crew membership semantics and InsuranceClaim's durable job snapshot/once-per-job redemption. This PR does not improvise these states inside Profile.purchases, which remains the receipt-ID boolean ledger. Product API access currently requires human resolution.

Validation: contract counts updated; existing suites and both Rojo projects must pass. Claude A reviews names, prompt flow and bonus display, then smoke-tests startup with the extra remotes. Codex implements pass verification/prompt guards only after approval; Claude A implements client UI in their lane. Human performs real purchase and saved-rejoin acceptance tests.
